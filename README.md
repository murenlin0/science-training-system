# Science-training-system

力量訓練設計規則庫。先問這次要練哪些主項，再按規則排課、估重量、改表、當日指揮。不是網站，也沒有預設三大項。

規則分四層：L0 是算術（算錯就改），L1 是原則（要 A 級文獻才動），L2 是數字與菜單（可討論），L3 是可拔掉的工具。MEV／MAV／MRV 只當參考，不當合格／不合格。

## 怎麼裝

把整個資料夾放到你使用的 AI 助理的 skills／專案路徑，讓它能讀到根目錄的 `SKILL.md`。只把網址傳給機器人，通常**不會**自動裝好，還是要本機收一次檔。

選手真實姓名、課表、日誌放 `user/`（已 gitignore）。倉庫裡的 `athlete_profile.example.yaml` 和 `templates/session.example.html` 是空模板。只有你說「用存檔」時，助理才讀 `user/`。當日真源是 `user/session.html`，對話裡的表只是渲染。

```
pip install pyyaml pytest
python -m pytest tests -q
```

## 怎麼用

跟助理講話即可，它會照 `SKILL.md` 只開一頁流程。

| 你說的大概是 | 它該做的事 |
|--------------|------------|
| 幫我排課／排一週 | 先問主項。沒答完不准套深蹲臥推硬拉，也不准套肩推、引體、俄挺。選完主項只查該動作的輔助表。 |
| 幫我估 PR／1RM | 先問哪個動作。槓鈴用外載；引體、雙槓這類把體重算進去（L = 體重 + 掛重，百分比打在 L 上）。俄挺、前水平沒有公斤 1RM，沒測過最大秒就只安排測試。 |
| 容量太大／想換動作 | 每次只改一兩件事，優先砍輔助。 |
| 為什麼／該不該 | 只答原理，不自動出表。 |
| 只要有氧／GPP | 用實測心率算區間，不用 220 減年齡。有力量課表時，體能填剩餘預算，不反向改主項。 |
| 開練、回報一組、下一組 | 只改今天剩下的。每組立刻寫進 `user/session.html`。對話貼表只是渲染，不要當存檔。 |
| 這篇論文要不要進規則 | 先判層再改檔。單篇試驗不改 L1。 |

排課、改表、回報組時，回覆末段會附肌群容量。開頭兩行是：每肌群每週大約至少 10 組、直接動作約算 1 組、協同約算 0.5 組；然後才是各肌群的 MEV／MAV／MRV 粗估。數字不當擋門。

一周幾練看你這份課表怎麼排，不寫死週一或四練。若離本週第一練已經約一週、後面幾練還沒做，助理要先問你：開下一週（沒跑的留空），還是先跑完再算同一週。

## 三種動作怎麼算重量

- **P**（槓鈴肩推、蹲、臥等）：百分比打在外載 1RM。
- **B**（負重引體、負重雙槓）：百分比打在 L。掛重 = 目標 L − 體重。程式參數是 `one_rm_added`（掛重 1RM）或 `system_1rm_L`（整段 L）。
- **I**（俄挺、前水平）：工作組用最大保持秒數的 60–70%。沒測過就先測。

回訓期不用舊的 1RM 當起點。

## 目錄

| 路徑 | 用途 |
|------|------|
| `SKILL.md` | 分流：一句話該讀哪一頁 |
| `workflows/` | 各功能一頁 |
| `core/` | 分類、負荷、e1RM、心率、輔助查表、容量審計 |
| `config/` | 輔助菜單、參數、肌群 landmarks 與權重 |
| `guardrails/` | L1 原則 |
| `literature/` | 薄摘，不貼原文 |
| `templates/` | 課表／日誌骨架 |
| `user/` | 你的真資料（不上傳） |

改 `config/volume_weights.yaml` 之後，下一則訓練回覆的權重列和組數會跟著變。只想本機自訂、不送 PR：可放 `user/volume_weights.yaml`（格式同檔、須含 `movements`），見 `CONTRIBUTING.md`。

## 貢獻動作與權重

**歡迎 PR 新增 `config/volume_weights.yaml` 裡的動作與肌群權重**（直接 ≈1.0、協同 ≈0.5；更細小數請標教練粗估）。沒列到的動作不計容量——不要瞎猜。肌群名須對齊 `config/volume_landmarks.yaml`。步驟與檢查清單見 **[CONTRIBUTING.md](CONTRIBUTING.md)**。
